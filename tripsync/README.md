# TripSync

**지능형 UI/UX 프로그래밍 · 5조**

그룹 생성부터 여행 일정 계획까지 지원하는 **완전 오프라인 JavaFX 데스크톱 앱**.

---

## 왜 완전 오프라인인가

교수님 피드백에 따라, 이 프로그램은 **GUI 애플리케이션 창 하나 안에서 모든 기능이 끝난다.**

사용하지 않는 것:

| 항목 | 사용 여부 | 이유 |
|---|---|---|
| WebView / 내장 브라우저 | ✗ | 웹 페이지를 띄우면 "GUI 앱 하나"라는 조건에서 벗어난다 |
| 지도 API (Kakao / Google) | ✗ | 외부 서버 호출이 필요하고 API 키 관리 부담이 있다 |
| WebSocket | ✗ | 실시간 동시 편집을 구현 범위에서 제외했다 |
| 원격 DB (PostgreSQL / Firebase) | ✗ | 서버 없이 로컬 파일로 저장한다 |

**지도는 포기하지 않았다.** JavaFX `Canvas` 에 좌표를 직접 그려 오프라인 벡터 지도를
렌더링한다 (5단계). 외부 요청이 0회이므로 인터넷이 끊긴 교실에서도 똑같이 동작한다.

---

## 기술 스택

| 항목 | 선택 |
|---|---|
| 언어 | Java 17+ |
| GUI | JavaFX 21 (FXML + CSS) |
| 저장소 | SQLite (로컬 `.db` 파일 1개) |
| 빌드 | Maven |
| 지도 | JavaFX Canvas 직접 렌더링 (GeoJSON, 오프라인) |

## 실행 방법

### 준비물
- JDK 17 이상 (`java -version` 으로 확인)
- Maven (IntelliJ / Eclipse 에 내장된 것을 써도 된다)

### 터미널에서 실행
```bash
mvn clean javafx:run
```

### IntelliJ IDEA 에서 실행
1. `File → Open` 으로 이 폴더를 열면 Maven 프로젝트로 자동 인식된다
2. 의존성 다운로드가 끝날 때까지 기다린다
3. `src/main/java/com/tripsync/Launcher.java` 를 우클릭 → `Run 'Launcher.main()'`

> `TripSyncApp` 을 직접 실행하면 *"JavaFX runtime components are missing"* 오류가 날 수 있다.
> `Launcher` 를 거치면 VM 옵션 설정 없이 실행된다.

## 폴더 구조

```
src/main/java/com/tripsync/
├── TripSyncApp.java          앱 진입점, 창과 레이아웃 구성
├── Launcher.java             IDE 실행용 보조 진입점
├── nav/                      화면 이동
│   ├── Route.java            화면 목록 (7개)
│   ├── Router.java           FXML 을 갈아끼우고 히스토리를 관리
│   ├── RoutedController.java 화면 간 값 전달 인터페이스
│   └── AppBar.java           항상 떠 있는 상단 바
│   └── AppContext.java       지금 보고 있는 모임/여행을 기억
├── controller/               화면별 컨트롤러 (FXML 과 1:1)
├── model/                    Group, AppUser … 불변 데이터 객체
├── data/                     SQLite 연결과 저장소
│   ├── Database.java         연결·스키마 적용·종료
│   ├── GroupRepository.java  모임 생성/조회/참여
│   └── UserRepository.java   로컬 프로필과 설정값
├── ui/                       재사용 컴포넌트 (사이드바, 빈 상태, 카드, 토스트)
└── util/                     초대 코드 생성 등

src/main/resources/com/tripsync/
├── view/                     FXML 레이아웃 7개
├── db/schema.sql             테이블 정의 (앱 시작 시 자동 적용)
└── css/app.css               디자인 시스템 (색·간격·컴포넌트)
```

### 계층 구조

```
Controller  →  Repository  →  Database  →  tripsync.db
 (화면)        (SQL)         (연결)
```

컨트롤러는 SQL 을 직접 쓰지 않고, 저장소는 화면을 모른다.
덕분에 4단계에서 일정 CRUD 를 붙일 때 기존 화면 코드를 건드릴 일이 없다.

---

## 화면 흐름

```
① 모임 목록 ──┬─ ② 모임 만들기 ──┐
              └─ 초대 코드 참여 ──┴─→ ③ 모임 상세 (여행 목록)
                                           │
                                           ├─→ ④ 여행 만들기
                                           └─→ ⑤ 여행 상세 ─┬─→ ⑥ 일정 추가/수정
                                                             └─→ ⑦ 공동 위시리스트
```

화면을 추가할 때는 `Route` 에 상수를 하나 넣고 같은 이름의 FXML 을 만들면 된다.
컨트롤러끼리는 서로를 모른 채 `Router.navigate(...)` 한 줄로 이동한다.

## 개발 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 프로젝트 골격 · 디자인 시스템 · 화면 라우팅 | ✅ 완료 |
| 2 | 도메인 모델 · SQLite 저장소 · 모임 생성/참여 | ✅ 완료 |
| 3 | 모임 상세 · 여행 생성 및 목록 | ⬜ |
| 4 | 여행 상세 3분할 · 일정 CRUD | ⬜ |
| 5 | 공동 위시리스트 · 오프라인 벡터 지도 | ⬜ |

### 1단계에서 완료된 것
- Maven + JavaFX 프로젝트 구성, 한 번에 실행 가능
- 7개 화면 전부 버튼으로 이동 가능 (설계서 11장 1단계 완료 기준)
- 디자인 시스템 CSS: 색 토큰, 버튼 4종, 입력, 카드, 패널, 빈 상태, 토스트
- 입력 검증 UI: 필수/선택 구분, 오류 메시지 위치, 포커스 이동
- 빈 상태 컴포넌트 (설계서 10장)

### 2단계에서 완료된 것
- SQLite 연결과 스키마 (`db/schema.sql`), 테이블 7개
- 모임 생성 / 초대 코드 참여 / 모임 목록이 **실제로 저장되고 재조회된다**
- 로컬 프로필 전환 — 한 PC 에서 초대 코드 참여 흐름을 끝까지 시연할 수 있다
- 디자인 2차: 왼쪽 사이드바, 파란색 팔레트, 카드 그림자 (설계서 참고 이미지 반영)
- 저장 실패 시 입력값을 유지하고 재시도를 안내 (설계서 10장)

### 아직 안 된 것
- 여행 생성·일정·위시리스트는 화면만 있고 저장되지 않는다 (3~5단계)
- 코드 안에 `[3단계에서 추가]` 같은 주석으로 교체 지점을 표시해 두었다

## 데이터는 어디에 저장되나

```
Windows   C:\Users\사용자명\TripSync\tripsync.db
macOS     /Users/사용자명/TripSync/tripsync.db
```

SQLite 파일 하나다. 이 파일을 지우면 앱이 처음 상태로 돌아간다.
프로젝트 폴더가 아니라 홈 폴더에 두는 이유는, IDE·터미널·jar 중 무엇으로 실행하든
작업 디렉터리가 달라져도 항상 같은 파일을 쓰게 하기 위해서다.

`.gitignore` 에 `*.db` 가 들어 있어 팀원 각자의 데이터는 커밋되지 않는다.

## 초대 코드 참여 시연 방법

서버가 없어서 다른 PC 와 데이터를 주고받을 수는 없다. 대신 **로컬 프로필**을
바꿔가며 한 PC 안에서 참여 흐름 전체를 보여줄 수 있다.

1. 사이드바 맨 아래 프로필 버튼 → `＋ 새 프로필 추가` 로 `이서준` 을 만든다
2. 다시 `나` 로 전환하고 모임을 하나 만든다 → 초대 코드가 발급된다
3. 모임 상세에서 `복사` 를 눌러 코드를 복사한다
4. 프로필을 `이서준` 으로 바꾼다 → 모임 목록이 비어 있다
5. 초대 코드를 붙여넣고 `코드로 참여` → 모임이 목록에 나타나고 참여자가 2명이 된다

중복 참여와 코드 중복은 애플리케이션 코드가 아니라 **DB 제약**(PRIMARY KEY, UNIQUE)으로
막혀 있다.

## 범위에서 제외한 기능

설계서 4.2 에 따라 아래는 만들지 않는다. 발표에서도 구현된 것처럼 말하지 않는다.

- 웹 서비스 및 모바일 앱
- 실시간 동시 편집, WebSocket
- 친구 검색, 1:1 메시지, 알림
- AI 공강 추천, TSP 자동 경로 최적화
- 여행 종료 후 사진 다이어리
- 투표, 드래그 앤 드롭 일정 편집

> 초대 코드는 **이 프로그램 안에서 모임 참여 흐름을 시연하기 위한 장치**다.
> 서버가 없으므로 다른 PC 의 사용자와 실제로 데이터가 공유되지는 않는다.
